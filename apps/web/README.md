# @lexvm/web — the LexVM player

The offline-first player for LexVM content packs: a vanilla TypeScript PWA
(see [ADR 0009](../../docs/adr/0009-vanilla-typescript-ui.md)) built with Vite.
It is published to GitHub Pages and also ships as one self-contained HTML file.

## Scripts

Run from the repository root (`-w @lexvm/web`) or from this directory.

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server. Run `npm run packs` at the root first to get the built-in packs. |
| `npm run build` | Type check, single-file build, main build (in that order, see below). |
| `npm run preview` | Serve `dist/` on <http://localhost:4173/>. |
| `npm run e2e` | Playwright tests against the preview server (build first), on iPhone and Pixel viewports. `e2e/walkthroughs.spec.ts` wins every built-in pack by tapping alone. |
| `npm run icons` | Re-render `public/icons/*` from `scripts/icon-art.ts` with Playwright's Chromium. |

Unit tests live in `test/` and run with the root `npm test` (Vitest, no DOM).

## Build outputs

`npm run build` produces `dist/`, ready to upload to any static host:

- `index.html`, `assets/*` — the app (hashed file names). The YAML compiler is a
  separate chunk loaded only by the "Create" screen.
- `packs/index.json`, `packs/*.lexpack.json` — built-in packs, copied from
  `public/packs/` (generated by `npm run packs`, not committed).
- `manifest.webmanifest`, `icons/*` — PWA metadata.
- `lexvm-offline.html` — the whole app in one file (JS, CSS and the built-in packs
  inlined, no service worker). Works from `file://`; offered as a download.
- `sw.js` — generated service worker. It precaches every file above under a cache
  name derived from their content hash, serves them cache-first, and falls back to
  the cached `index.html` for navigations. A new deployment shows an
  "update available" toast; the new version activates when the player reloads.

The single-file build (`vite build --mode singlefile`, output in `dist-offline/`)
runs first so that the main build can copy it into `dist/` and precache it.

Everything uses relative URLs (`base: "./"`) and hash routes (`#/play/builtin/<id>`),
so the same build works at `https://<user>.github.io/lexvm/`, on a local server and
from `file://`.

## Structure

```
src/
  main.ts            bootstrap (settings, router, service worker)
  app.ts             hash router and screen lifecycle
  i18n.ts            German and English UI strings
  dom.ts icons.ts    DOM builder (text nodes only, never innerHTML) and line icons
  screens/           library, game, create (lazy), settings, about
  components/        transcript, dock, action sheet, sheets/dialogs, hints, ending, toasts
  game/session.ts    running game: state, command log, undo stack, save/restore
  logic/             pure, unit-tested helpers (catalog, saves, action sheet rules, routes)
  services/          engine, packs, saves, storage (IndexedDB → localStorage → memory), PWA, settings
  sw.ts              service worker source (transpiled by build/plugins.ts)
build/               Vite plugins: built-in packs module, single-file HTML, service worker, CSP meta tag
```

Rules that keep the player safe and robust:

- Pack text and imported files are untrusted: they are only ever rendered with
  `textContent` (enforced by `test/styles.test.ts`).
- Every pack is validated with the engine's `loadPack` before use, including
  built-in and stored packs.
- Storage failures never break the game; saves fall back to memory.
- Nothing calls into the engine at import time.
